TMMT OS Dispatch System

How jobs flow from staff intake → protocols → your GHL locations
May 2026 · TMMT × AIXMOS

One sentence: You or staff enter a dispatch job in TMMT OS → the system saves a ticket, runs protocols (routing, ClickUp, GHL tags, dispatch loads) → each configured GHL location receives a webhook → GHL workflows create contacts, deals, tags, and tasks.

1. The big picture (simple)

RoleWhat it is
TMMT OSCommand center — front desk where jobs are entered and tracked
Local vendorNearby shop that outsources work to TMMT (“handle this pickup for us”)
GHL locationEach TMMT app/brand sub-account (Rentals, Moving, Vendor Connect, etc.)
Inbound webhookThe “doorbell” in GHL — TMMT rings it when a job is created
WorkflowWhat happens inside GHL after the doorbell rings (contact, deal, SMS, task)

2. End-to-end flow

YOU / STAFF │ ▼ /internal/dispatch/new (or API POST /api/jobs/dispatch) │ ▼ TMMT OS — create case + protocol_runs │ ├──► Routing engine (work type, ClickUp task, agent draft) ├──► dispatch_loads row (pickup / dropoff) ├──► GHL tags on main Rentals contact (if GHL connected) ├──► Optional: assign TMMT network vendor (vendor_jobs) │ ▼ POST flat JSON to each GHL inbound webhook (PARTNER_APP_WEBHOOKS_JSON) │ ▼ GHL workflow per location: Contact → custom fields → Opportunity → tag → notify → task

4. Protocol chain (automatic)

Every staff dispatch job runs these steps (logged in protocol_runs):

  1. Intake created — customer_intake_forms + cases row
  2. Routing — detect work type, optional ClickUp task
  3. Dispatch load — pickup/dropoff in dispatch_loads table
  4. Agent draft — TANK/STICKS checklist on case
  5. GHL notify — tags / stage sync on main account
  6. Vendor assignment — if TMMT vendor selected on form
  7. Partner delivery — POST to each configured GHL webhook

10. Affiliate / third-party apps

If an “app” is only access via someone else’s affiliate link (you don’t control GHL):

  • Jobs stay in TMMT OS (cases + vendor portal)
  • Use Zapier/Make if the affiliate allows automation
  • Staff handoff via /internal/dispatch/new or ops command

For locations you control (your 4 GHL sub-accounts), use inbound webhooks as described above.
